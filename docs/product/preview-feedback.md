# Preview feedback

The normal, calm session and software preview viewers use the existing Composer. There is no destination selector, extra chat heading or URL checkbox. A session preview supplies its existing session and project. A software preview supplies its project/repository to GET /api/preview/target. The server chooses an existing controllable session; when none matches, the viewer reports an error and preserves the draft without sending anything. Legacy prepared payloads with a null destination are rejected too; they are never silently retargeted. No agent or session is created by the viewer.

A send requires a fresh capture of the displayed iframe. The current implementation uses browser Region Capture (getDisplayMedia + CropTarget/cropTo), not a stored software screenshot or a server visit to the URL. Choosing an unrelated tab cannot satisfy the crop target. Same-origin URL, viewport and scroll must match before and after capture. A cooperative cross-origin page can expose metadata using the nonce/source/origin checked `weevils:preview-view?` / `weevils:preview-view` protocol; metadata alone is never accepted as pixel evidence.

**Known limitation:** no metadata bridge is currently installed in the TLO cross-origin preview. Browsers without native Region Capture, including the iPhone scenario reported in IMG_7309, cannot take this automatic capture through the available web implementation. The viewer must retain the draft and report an actionable error without posting any message. It does not fall back to stale images, DOM reconstructions, or an uncaptured text-only send. Native desktop capture still requires the browser's capture permission UI. No actual browser/device capture was verified during this change.

After capture succeeds, the target, original text, current page context and image are persisted together in the existing IndexedDB payload store before the attachment API can run. A retry after navigation or reload uses those same bytes and destination, preserving the existing outbox fingerprint/idempotency identity. A failed capture or failed persistence never reaches the attachment API. Successful submissions follow replies from the actual target without remounting the website iframe.

Validation: component tests cover the standard composer, automatic target/fallback, retained drafts, double submission protection, capture/persistence failures, exact payload reuse through reload/navigation and replies. Capture tests cover the native pixel source/crop target, changed scroll, unsupported capabilities and failed cropping. These are mocked browser capability tests, not visual QA or proof of an iOS screenshot.
